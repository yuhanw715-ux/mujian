MUJIAN / 1.2.0

把两份日常，重新收好

继续用原仓库。先复制新版文件，再上传、构建、签名。

先在手机里导出一次完整备份。

打开暮笺 → 右上角设置 → 导出完整备份 → 保存到“文件”。新版可以读取旧版日记；签名工具能否保留覆盖安装的数据仍取决于它自己的行为，因此先留一份备份。

1 · 找到两个文件夹

下载最新的 Mujian-Source.zip，解压到一个临时的新位置，进入里面的 Mujian。这是“新版文件夹”。

再打开你上次成功执行上传命令的 Mujian 文件夹。这是“原文件夹”。它也有 App、scripts 和 project.yml，并保留着原来的 Git 仓库信息。

不要删除原文件夹，也不要把新版整个 Mujian 文件夹套进去形成 Mujian/Mujian。

2 · 复制并替换内容

  1. 在新版文件夹中，按 Ctrl+A 全选里面的文件和子文件夹。
  2. 按 Ctrl+C 复制。
  3. 切换到原文件夹，按 Ctrl+V 粘贴。
  4. Windows 提示同名文件时，选 替换目标中的文件。

完成后，原文件夹中应能找到新文件 scripts/update-github.sh，以及 App/Core/DiaryPresentation.swift。

3 · 上传到原来的 GitHub 仓库

在原文件夹的空白处右键，选择 Git Bash Here。只输入下面这一行并按回车：

bash scripts/update-github.sh

等到最后显示“更新已上传”，就完成了。如果出现“请把新版源码中的文件复制到之前上传成功的 Mujian 文件夹”，说明打开的是新解压的独立文件夹，请回到原文件夹操作。

如果找不到原文件夹，先在空文件夹打开 Git Bash，输入 git clone ，后面接你现有暮笺仓库的 HTTPS 地址。克隆完成后，把新版文件复制到克隆出来的仓库文件夹，再在那里执行更新命令。不要另建第二个暮笺仓库。

4 · 再运行一次构建

  1. 打开原来的暮笺 GitHub 仓库，不是待办的 miu-memo。
  2. 顶部点 Actions。
  3. 左侧点 Build iOS IPA。
  4. 右边点 Run workflow；选择 main，再点绿色 Run workflow。
  5. 打开新出现的运行记录，等待绿色 Success。
  6. 在这个新记录的 Summary → Artifacts 下载 Mujian-IPA。

不要点旧构建记录的 Re-run，那可能重新构建旧代码。需要从 main 发起一次新的运行。

5 · 签名安装

解压下载的 ZIP，把 Mujian-unsigned.ipa 交给原来的签名工具。尽量沿用原来的签名身份和应用标识 app.miu.mujian，按工具支持的方式覆盖安装。

安装后在设置最下方确认显示 1.2.0。不要先卸载旧 App；如果工具要求卸载，先确认你已经导出了备份。

这一版怎么用？

  1. Miu 的日记：月历 / 日记栏 → 进入具体一天 → 点 Miu 卡片 → 才显示全文。导入时也只核对信息，不显示 Miu 正文。
  2. 写作颜色：写日记或导入小暮暮的 TXT 时，选“当日写下”（暮紫）或“后来补写”（青色），再收藏。这里按实际写作时间选择，不按导入时间。
  3. 给旧日记补选颜色：点开小暮暮日记全文 → 右上角“…” → 选择标记。旧日记显示灰色“未标记”，不会自动猜测或覆盖正文。
  4. 核对篇数：底部“日记” → 看两位作者的总篇数 → 点“篇数不同”，查看每个日期的差异；再次点击可取消筛选。
  5. 共享背景：月历设置的图片、图层、主题会直接用于日记栏；不需要再设置一次。

Miu 的隐藏正文不参与概览搜索，可通过日期或作者查找。小暮暮的文字仍可正常搜索。完整内容与标题始终保留在本机，展开阅读时才显示。

新版可读取旧日记和备份；新版保存的数据和导出的备份，需要 1.2 或更新版本读取。

功能操作
白昼 / 暗夜 / 强调色设置 → 主题与颜色 → 选好后保存
猫爪开关设置 → 主题与颜色 → 暗夜的小猫爪

“置顶”是点一次执行一次的动作，没有常亮开关。所有装饰图位于背景上方、日历文字和按钮下方，平时不会挡住日期操作。最多可放 12 张，位置、透明度和叠放顺序会保存到本地及完整备份。

如果构建变红

展开红色步骤，截取最早出现的 error: 附近，或下载 Mujian-build-log 发给 Miu。不需要发送日记正文。

这一版已经通过核心规则和语法检查；完整 iOS 编译、真实手势和玻璃效果仍要由本次 GitHub 构建和手机运行确认。
