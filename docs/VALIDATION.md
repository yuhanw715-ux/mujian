## 已实际执行

- 使用 Swift 官方 Linux 工具链 6.0.3，按 Swift 5 语言模式编译 `DiaryModels.swift`、`DiaryRules.swift` 和 `Tests/CoreTests.swift`，运行结果为 **46 项检查通过**。
- 使用 Swift 编译器 `-frontend -parse` 对全部原生 UI、存储和 App 入口 Swift 文件做语法解析，未发现语法错误。
- shell 脚本通过 `bash -n`；XcodeGen 和 GitHub Actions YAML 可正确解析；图片资源引用存在。
- App 图标为 1024 × 1024、不透明 RGB PNG；默认插画为 1024 × 1536 PNG。
- 源码包仅包含项目源码、虚构测试文字、生成插画、图标和说明。没有用户真实 TXT、私人日历内容、证书或 API Key。

核心测试覆盖：文件名日期的多种格式、缺少年份、非法日期、闰年、多日期歧义、四 / 五 / 六行月历、UTF-8 / UTF-16、BOM、Windows 换行、空行和 emoji、空白和过大文件、多于两篇日记、重复导入判定、备份正文 / 草稿 / 图片往返、亚秒时间戳、重复恢复、较新内容和删除状态优先，以及无效版本、缺失图片和越界图片路径拒绝。

## 手机上建议先试一次

1. 用虚构文字写一篇“我写的”，保存后关闭、重开 App，确认文字仍在。
2. 导入一个带日期的虚构 TXT，确认出现在相应日期；再导入一个无日期文件，确认必须选择日期。
3. 在同一天添加第三篇，确认能全部打开。
4. 更换单日背景，确认月历没有背景图；旋转屏幕确认卡片重排。
5. 写一份草稿，点“稍后再写”，到草稿箱继续；编辑已存在的日记时，原文在正式收藏前保留。
6. 导出完整备份，恢复同一备份，确认没有产生重复日记。
7. 将一篇测试日记移到回收站，再恢复，确认它回到原日期。

这些步骤仅用虚构内容即可。排错只需构建错误或不含私密内容的界面截图，不需要发送日记正文。
